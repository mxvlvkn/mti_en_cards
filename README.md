# MTIEN — английский по карточкам

Статический тренажёр английских слов для GitHub Pages: флеш-карточки,
интервальные повторения, короткие тесты и статистика. Без сборки и без
зависимостей — чистые HTML/CSS/JS (ES-модули).

Работает в двух режимах:

- **локальный** (по умолчанию) — прогресс в `localStorage`, ни одного сетевого
  запроса, аккаунт не нужен;
- **синхронизация** — если заполнить `assets/js/config.js` и выполнить
  `sql/schema.sql` в Supabase, прогресс едет между устройствами через аккаунт.

## Что умеет

- 4 колоды, 64 карточки: повседневное (A1), путешествия (A2), работа (B1),
  фразовые глаголы (B2);
- интервальные повторения: «не знаю» → через 10 минут, «знаю» → 1, 2, 4, 8, 16 дней;
- лицевая/обратная сторона, транскрипция, пример с переводом;
- озвучка слов (Web Speech API, работает офлайн в Chrome/Edge/Safari);
- тест с четырьмя вариантами ответа;
- статистика: серия дней, выучено, точность, календарь за 30 дней;
- светлая/тёмная тема, автоопределение системной;
- адаптив: телефон от 320 px, планшет, ноутбук, десктоп;
- офлайн-режим (service worker) и установка на домашний экран (PWA);
- экспорт/импорт прогресса в JSON.

## Локальный запуск

ES-модули не работают по `file://`, поэтому нужен любой статический сервер:

```bash
npm run dev          # http://127.0.0.1:8080 (если порт занят — возьмёт следующий)
# или
python -m http.server 8080
```

Проверка синтаксиса модулей: `npm run check`.

Опционально — автотест вёрстки в реальном Chrome (скриншоты в `_shots/`,
поиск ошибок консоли и горизонтального скролла на 320/390/768/1440 px):

```bash
npm i -D puppeteer-core
node scripts/visual-check.mjs
```

## Деплой на GitHub Pages

1. Создайте репозиторий (для бесплатного Pages он должен быть **публичным**).
2. Положите **содержимое** папки `english-cards` в корень репозитория —
   `index.html` должен оказаться в корне, а не внутри вложенной папки.
3. `git push` в ветку `main`.
4. В репозитории: **Settings → Pages → Build and deployment → Source:
   GitHub Actions**. Workflow `.github/workflows/pages.yml` задеплоит сайт сам.
5. Через минуту сайт будет доступен по адресу
   `https://<username>.github.io/<repo>/`.

Все пути в проекте относительные, поэтому подпапка репозитория не мешает.
Роутинг на хешах (`#/study/everyday`) — обновление страницы не даёт 404.
В артефакт попадают только `index.html`, `404.html`, `manifest.webmanifest`,
`sw.js`, `.nojekyll` и `assets/` — `node_modules`, скрипты и README не деплоятся.

Свой домен: **Settings → Pages → Custom domain**, плюс DNS-запись CNAME на
`<username>.github.io`.

> GitHub Pages по правилам не предназначен для коммерческих сайтов и SaaS.
> Для личного/учебного проекта — ок; для продукта берите Cloudflare Pages
> или Netlify.

## Настройка Supabase (синхронизация)

Нужна только если хотите аккаунты и общий прогресс на нескольких устройствах.

1. **Создайте проект** на [supabase.com](https://supabase.com) (Free-тариф:
   2 проекта, 500 МБ базы, 50 000 пользователей).
2. **Выполните схему.** SQL Editor → New query → вставьте `sql/schema.sql` →
   Run. Скрипт создаёт таблицы `profiles`, `card_progress`, включает RLS и
   политики «только свои строки».
3. **Возьмите ключи.** Settings → API:
   - `Project URL` → `supabaseUrl`;
   - `anon public` → `supabaseAnonKey`.
4. **Впишите их** в `assets/js/config.js`:
   ```js
   export const CONFIG = {
     appName: 'MTIEN',
     supabaseUrl: 'https://xxxx.supabase.co',
     supabaseAnonKey: 'eyJhbGciOi...',
     tables: { progress: 'card_progress', profiles: 'profiles' }
   };
   ```
5. **Настройте Auth.** Authentication → URL Configuration:
   - Site URL: `https://<username>.github.io/<repo>/`;
   - Redirect URLs: тот же адрес.
   Authentication → Providers → Email: включён по умолчанию. Если не хотите
   подтверждать почту на каждом шаге — отключите «Confirm email» (для
   тестового проекта; для реального лучше оставить).
6. Перезапустите деплой (или обновите страницу). В настройках появится
   «Войти», в шапке — статус аккаунта.

### Что происходит с данными

- при входе локальный прогресс сливается с облачным: побеждает более свежая
  запись по каждой карточке (`updated_at`);
- после слияния всё отправляется обратно в `card_progress`;
- оценки сохраняются с задержкой ~1,5 с (debounce), батчами по 400 строк;
- настройки (тема, цель, направление) остаются локальными.

## Что нужно донастроить — чек-лист

- [ ] **Репозиторий.** Публичный (для бесплатного Pages), файлы в корне,
      ветка `main` совпадает с workflow.
- [ ] **Pages.** Settings → Pages → Source = GitHub Actions; после первого
      пуша проверить, что job `deploy` зелёный.
- [ ] **Свой контент.** `assets/js/data.js`: заменить/дополнить колоды.
      `id` карточек не меняйте после начала занятий — к ним привязан прогресс.
- [ ] **Supabase (опционально).** `sql/schema.sql` выполнен, URL и anon key
      вписаны в `config.js`, Site URL в Auth указывает на адрес Pages.
- [ ] **Проверка RLS.** В Supabase → Table Editor → `card_progress` должно быть
      «RLS enabled». Быстрый тест: откройте сайт без входа и убедитесь, что
      данные не подгружаются (политики пускают только `authenticated`).
- [ ] **Иконки/название.** `manifest.webmanifest`, `assets/icon.svg`, `<title>`.
- [ ] **Домен (опционально).** Custom domain + CNAME.
- [ ] **Резервные копии.** На Free-тарифе Supabase бэкапов нет — периодически
      делайте экспорт из настроек приложения (JSON) или `pg_dump`.

## Как добавить свои карточки

`assets/js/data.js`:

```js
{
  id: 'my-deck',
  title: 'Моя колода',
  subtitle: 'Тема и описание',
  level: 'B1',
  icon: 'i-spark',        // id иконки из спрайта в index.html
  color: '#2f6db5',
  cards: [
    {
      id: 'my-01',        // уникальный и постоянный
      en: 'serendipity',
      ru: 'счастливая случайность',
      ipa: 'ˌserənˈdɪpəti',
      pos: 'сущ.',
      example: 'It was pure serendipity.',
      exampleRu: 'Это была чистая случайность.'
    }
  ]
}
```

Иконки: `i-spark`, `i-arrow`, `i-cards`, `i-bolt`, `i-clock`, `i-info`.
Чтобы добавить новую — вставьте `<symbol id="i-имя" viewBox="0 0 24 24">…</symbol>`
в sprite в начале `index.html`.

## Как работает повторение

У каждой карточки «коробка» 0–5. Ответ «знаю» поднимает на одну вверх,
«не знаю» сбрасывает в 0. Интервалы: 10 минут, 1, 2, 4, 8, 16 дней.
Занятие собирается из просроченных карточек, затем новых — до дневной цели.
Кнопка «Повторить всё равно» (`?practice=1`) игнорирует расписание.

## Безопасность

- В браузере лежит **только** `anon`-ключ Supabase. Он публичен по дизайну:
  это не секрет, а идентификатор проекта.
- Доступ к строкам ограничивают RLS-политики: `auth.uid() = user_id`.
  Даже с ключом и знанием API чужой прогресс не читается.
- `service_role` key обходит RLS. Его нельзя вставлять в `config.js`,
  в код фронтенда или в переменные, доступные браузеру. Только сервер/CI.
- Прямого подключения к Postgres из браузера нет — только HTTPS API Supabase.
- Секреты деплоя (если появятся) — в GitHub Actions Secrets, не в репозитории.

## Возможные проблемы

| Симптом | Причина и решение |
| --- | --- |
| Пустая страница, в консоли `Failed to load module` | Открыт `file://`. Нужен http-сервер. |
| После обновления видна старая версия | Service worker отдаёт кэш. Поднимите `VERSION` в `sw.js` и перезагрузите дважды. |
| «Войти» нет в настройках | Не заполнены `supabaseUrl`/`supabaseAnonKey` в `config.js`. |
| `new row violates row-level security policy` | Не выполнен `sql/schema.sql` или политики не создались. |
| Письмо с подтверждением не приходит | Проверьте Site URL и папку «Спам»; на Free-тарифе есть лимит писем. |
| Прогресс пропал после очистки браузера | Данные живут в `localStorage`; включите синхронизацию или делайте экспорт. |
